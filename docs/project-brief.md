## 1. 핵심 루프

```
한 걸음 옮긴다 → 몸이 한 겹 준다 → 먹이를 덮으면 는다 → 출구까지 몸을 남기고 간다
```

한 문장으로: **몸이 곧 연료이자 부피다.**

크기 하나가 세 가지를 동시에 정한다. 이게 이 게임의 전부다.

| 크기가 정하는 것 | |
|---|---|
| **얼마나 더 갈 수 있나** | 한 걸음에 −1. 0이 되면 못 간다 |
| **어디에 들어갈 수 있나** | 크기 N은 N×N 칸을 차지한다. 크면 좁은 데를 못 지나간다 |
| **얼마나 오를 수 있나** | 크기 N이면 N−1칸 턱까지 오른다 |

셋이 서로 반대로 당긴다 — **가려면 먹어야 하고, 먹으면 못 들어간다.**

### 왜 이 루프인가

떨어지는 건 공짜고 오르는 건 비싸다. 그래서 **지형이 곧 문제지**가 된다.
플레이어가 매 걸음 묻는 것은 하나다: *"지금 먹을까, 지나칠까."*

## 2. 규칙 전문 (이게 전부다)

1. 조작은 **← →** 둘뿐. 위아래는 중력과 몸집이 정한다
2. 한 걸음 = **크기 −1**. 덮은 먹이 하나당 **+1**. 불은 끄면서 **−1**
3. **중력** — 발밑이 비면 떨어진다. **낙하는 공짜**(크기가 안 변한다)
4. 앞이 막혔으면 **N−1칸까지 턱을 오른다**. 그것도 한 걸음이다
5. **몸은 가는 쪽으로 흐른다** — 먹고 자라면 앞이 부풀고, 줄면 뒤가 딸려온다
6. 크기가 0이 되거나 몸이 안 들어가는 걸음은 **불가**. 죽지 않는다 — 못 갈 뿐이다
7. 덩어리가 출구를 덮으면 클리어

> 🔴 **지는 게 없다.** 갇히면 되돌리거나 다시 하면 된다. 벌은 없다.

정본은 문서가 아니라 코드다 → `tools/engine.js`

## 3. 설계 원칙

### 🔴 원칙 1 — 규칙을 늘리지 않는다

지금 규칙은 일곱 줄이고, **출시까지 일곱 줄로 간다.**
난이도는 **지형과 먹이 배치**에서만 나온다. 새 물건(스위치·열쇠·적)을 넣고 싶어지면
[[decisions]]에 *"왜 지형으로는 안 되는가"*를 먼저 적는다.

### 🔴 원칙 2 — 판은 기계가 검증한 것만 넣는다

`tools/stamp.js`를 통과하지 않은 판은 게임에 안 들어간다. 통과 조건:
**풀린다 · 최단해가 하나뿐이다 · 표기값이 실제와 같다.**

근거: 손으로 그린 판 아홉 개 중 다섯 개만 풀렸다. 사람 눈으로는 구분이 안 된다.

### 🔴 원칙 3 — 되돌아가기가 0인 판은 판이 아니다

*"오른쪽만 누르면 풀린다"*면 결정이 없는 것이다. `stamp.js`가 `back` 값으로 잰다.
**출시 판의 절반 이상은 `back ≥ 1`이어야 한다.**

지금 상태: 6판 중 1판만 만족 — 이게 이 프로젝트의 **가장 위험한 가정**이다(§5).

### 원칙 4 — 규칙은 한 곳에만 있는다

JS(`tools/engine.js`)와 C#(`SlimeEngine.cs`) 두 벌이 존재한다. 이건 위험이다.
**적합성 검사**로 묶는다: `levels.json`의 정답 수순을 C#이 재생해서 클리어되는지 본다.
어긋나면 테스트가 깨진다.

### 원칙 5 — 아트는 이미 있는 것으로 간다

슬라임·불꽃은 사장님이 예전에 그리신 것을 GIF에서 되살렸다(`art/`).
**새로 그리는 건 3단계(분량) 이후.** 그릴 줄 아는 사람에게 도트는 가장 재밌고 가장 위험한 도피처다.

## 4. MVP 범위 — 여기까지 되면 올린다

기간은 안 정한다. **범위로 결승선을 긋는다.**

- [ ] 판 **20개**. 그중 **10개 이상이 `back ≥ 1`**
- [ ] 타이틀 → 판 고르기 → 플레이 → 클리어 → 다음 판 이 **끊김 없이** 돈다
- [ ] **되돌리기(Z) · 재시작(R)** — 무제한
- [ ] 어디까지 깼는지 **저장**된다
- [ ] 슬라임이 걷고 · 떨어지고 · 오르고 · 커지는 게 **눈으로 구분**된다
- [ ] WebGL 빌드가 itch.io에서 돈다

이 목록이 다 체크되면 **그날 올린다.** 더 붙이지 않는다.

## 5. 가장 위험한 가정

> **"먹이 배치만으로 결정이 생기는 판을 20개 만들 수 있는가?"**

지금 여섯 판 중 다섯이 *오른쪽만 누르면* 풀린다.
규칙은 서는데 **판이 아직 결정을 안 만든다.**

**검증 방법**: `tools/search.js`로 `back ≥ 2`인 판을 찾아본다.
**검증 비용**: 하루. JS라 한 판에 몇 초다.
**검증 통과선**: `back ≥ 2`인 판 **다섯 개**를 만들 수 있으면 20개도 만들 수 있다.

🔴 **이게 안 되면** — 규칙을 늘리기 전에 먼저 **판 크기와 먹이 밀도**를 바꿔 본다.
그래도 안 되면 축을 하나 더 얹는 걸 검토한다(순서·시간). 그때는 [[decisions]]에 적고 간다.
