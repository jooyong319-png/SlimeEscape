## 1. 🔴 확정 — 움직임

사장님 확인: *"굳 내가 원한 게 이거야."* / *"이걸로 움직임 게임 방식은 픽스."*

| | |
|---|---|
| 몸 | **칸의 사슬.** 머리가 앞, 시작 길이 1 |
| 이동 | 머리를 **상하좌우 한 칸**. 몸이 따라온다 (꼬리가 비켜난다) |
| 🔴 **중력** | **있다** (2026-08-28 확정). 몸이 통째로 떨어진다 — 자기 몸은 지지대가 못 된다 |
| 🔴 **오르기** | **위로 k칸 오르려면 길이가 k+1 이상.** 꼬리가 바닥을 짚어야 하니까 |
| 조각 | 먹으면 **길이 +1**. 그 걸음엔 꼬리가 안 비켜난다. **줄어드는 건 없다** |
| 막힘 | 벽·자기 몸에 부딪히는 걸음은 **막힌다.** 죽지 않는다 — 못 갈 뿐 |
| 되돌리기 | 무제한 (`Z`) · 재시작 (`R`) |
| 화면 | 판 하나가 화면 한 장 (20×12 고정). 카메라 안 움직임. 격자선이 보인다 |

**정본은 코드다** → `game/Assets/Scripts/SnakeEngine.cs`

### 🔴 중력이 바꾼 것

**짧으면 못 올라간다.** 그래서 **조각 먹는 순서가 저절로 강제된다** — 낮은 것부터 먹어
길이를 벌어야 높은 데로 간다. 규칙을 더 안 늘리고 순서 제약이 생겼다.

⚠️ **대가도 측정됐다** (`tools/exp-gravity.js`):
- 난이도(“이미 진 상태” 비율)는 **0.7% → 2.3%**로 올랐다
- 그런데 **상태 공간이 7분의 1**이 됐다 — 어려워진 게 아니라 **갈 수 있는 데가 줄었다**
- 시험판 셋 중 **하나는 아예 못 풀게** 됐다 (목표가 아래층이면 못 돌아온다)

🔴 그래도 넣기로 한 근거는 **사장님이 직접 해보고 고르신 것**이다.
손맛은 지표로 안 잡힌다 — 그게 이 결정의 유일한 근거이고, 충분한 근거다.

### 🔴 움직임 연출의 철칙

**연출은 칸을 건드리지 않는다.**
끌리는 느낌은 **위치를 어긋내서가 아니라 출발 시간을 늦춰서** 낸다.
걸음이 끝나면 모든 마디가 **정확히 자기 칸**에 앉는다.

> 이 원칙을 어겨서 두 번 깨졌다(스쿼시가 몸을 2.07칸으로 만든 것, 마디가 계단처럼 어긋난 것).
> **새로 움직임을 짤 때 이 줄을 먼저 읽는다.**

## 2. 🔴 확정 — 게임 방식 (2026-08-28)

설계 연구 7회차 결론. 근거 전문은 `docs/design-study.html`.

### 목표

> **판에 표시된 칸을 몸으로 정확히 채우면 문이 열린다.**
> 남아도 안 되고 모자라도 안 된다.

- **길이 = 목표 칸 수**여야 한다 → 조각은 **목표 칸 수 − 1개**
- **심(心)** — 목표 칸 중 하나에 표시된 자리. **머리가 마지막에 여기 있어야** 한다

### 세계관 (대사 없이 그림과 소리로만)

**버려진 기계 유적.** 문마다 빈 홈이 파여 있고, **몸이 곧 열쇠다.**
바닥의 **열쇠 조각**을 먹어 길이를 맞추고, 홈에 정확히 들어맞으면 자물쇠가 돈다.

- 색: 차가운 회청색 돌 + 놋쇠빛 홈. **슬라임만 따뜻한 색**
- 클리어: **묵직한 자물쇠 소리 하나.** 채우기는 끝이 밋밋해서 소리로 알린다

### 구성 — 갈라지는 유적

메뉴가 없다. 켜면 1번 방. 문을 열면 화면이 밀려 다음 방.
**몇 방마다 문이 둘 열리고 서너 방 뒤 다시 합쳐진다** — 막히면 되돌아가 다른 문으로 간다.

## 3. 설계 원칙

### 🔴 원칙 1 — 규칙을 늘리지 않는다

난이도는 **지형과 조각 배치**에서 나온다. 요소는 §4에 정해진 셋뿐이다.
넷째를 넣고 싶으면 §6을 열어보고 §7 절차를 따른다.

### 🔴 원칙 2 — 판은 기계가 검증한 것만 넣는다

**풀린다 · 최단해가 하나뿐이다 · 표기값이 실제와 같다.**
근거: 이전 리비전에서 손으로 그린 판 아홉 개 중 **다섯 개만** 풀렸다.

### 🔴 원칙 3 — 초록불을 의심한다

*"최단해가 유일한 판만 골랐다"*가 통과했는데, **고를 게 없어서** 유일한 거였다.
품질 지표를 만들면 **실패해야 마땅한 예를 넣어보고 빨간불이 켜지는지** 확인한다.

### 🔴 원칙 4 — 솔버는 난이도를 못 잰다

최단 수·유일성은 알아도 **"사람이 몇 분 걸리는가"**는 모른다.
그건 **틀린 길이 얼마나 그럴듯한가**로 정해진다.
→ **판을 어렵게 만드는 일은 사람이 한다.** 솔버는 정답만 지킨다.

### 원칙 5 — 규칙은 한 곳에만

JS(도구)와 C#(게임)에 규칙이 두 벌 생기면 **적합성 검사로 묶는다.**

### 원칙 6 — 재미 확인 전에 아트를 만들지 않는다

지금은 **그레이박스**다. 도트는 판 5개가 재밌다고 확인된 뒤.
⚠️ 예전 슬라임·불꽃 도트는 **뱀에 안 맞는다.** `art/`에 있지만 지금 게임의 것이 아니다.

## 4. MVP 범위

- [ ] **판 21개** (갈래 3번 포함) · 목표 **총 120분** · **판당 평균 6~7분**
- [ ] 요소 **셋** — 아래 셋만. 넷째는 없다
  - **① 끝나는 자리(심)** — 6번 방 도입
  - **② 머리 바꾸기** — 9번 방 도입. **판에 놓인 칸을 밟아서** 발동
  - **③ 머리 떼기** — 14번 방 도입. 남은 몸은 채워진 채 남는다. **판당 한 번만**
- [ ] 첫 화면: 제목이 **1번 방 위에 겹쳐** 뜨고 첫 걸음에 사라진다
- [ ] 되돌리기 · 재시작 · 진행 저장
- [ ] 🔴 **되돌리기는 "막히는 순간"에 처음 안내된다**
- [ ] WebGL 빌드가 itch.io에서 돈다

## 5. 🔴 가장 위험한 가정

> **"판이 충분히 어려운가?"**

판당 3~4분짜리가 나오면 21방으로도 **1시간**밖에 안 된다.
그리고 판을 어렵게 만드는 건 **처음 해보는 일**이다 —
*쉬운 판 50개는 노동이지만 어려운 판 10개는 재능이다.*

**검증 방법:** 판 5개를 만들어 **사람 3명에게 풀려 실제 시간을 잰다.**
**멈출 조건:**

| 결과 | 다음 |
|---|---|
| 평균 6분+ · *"한 판 더"* | 🟢 21방 계획대로 |
| 평균 3~4분 | 🟡 요소를 앞당기거나 판 설계를 다시 배운다 |
| *"뭘 하는지 모르겠다"* | 🔴 목표 표현이 문제. 설계 연구 4회차로 |
| *"지겹다"* | 🔴 **여기서 멈춘다.** 21방을 만들어도 안 된다 |

## 6. 🔴 안 할 것 목록

> **구분이 먼저다 (2026-08-28 추가):**
> 금지하는 건 **규칙을 늘리는 것**이지 **규칙을 설명하는 그림**이 아니다.
> 문에 새겨진 홈, 바닥의 음각, 유적의 기호는 **표현**이라 얼마든지 쓴다.
> (이 구분이 없어서 예전 목록이 좋은 아이디어까지 막았다)

### 규칙을 늘리는 것 — 금지

- **적 · 전투 · 죽음** — 막히기만 한다
- **넷째 요소** — 셋으로 못 채우면 판 설계가 문제지 요소가 부족한 게 아니다
  (예비 1순위: 큰 조각 +2. 그것도 §7 절차를 거친다)
- **주워서 쓰는 아이템 · 스위치 · 발판**
- **시간 제한 · 걸음 수 제한**
- **몸이 줄어드는 규칙** — rev.4에서 뺐다

### 스코프를 부풀리는 것 — 금지

- **스토리 · 컷신 · 대사** (세계관은 그림과 소리로만)
- **점수 · 별 3개 · 랭킹**
- **레벨 에디터 · 월드맵** (갈래로 대신한다)
- **음악** (효과음 3종은 마감 단계에)
- **새 도트** (판 5개 검증 전까지)
