### 15:33 — 🔴 재는 자가 틀려 있었다 (A 시작하자마자)

외길로 고르려고 못을 재려다 `tight` 의 정의를 확인했다:

```js
if (bad === alts) tight++;      // 다른 수가 **전부** 지는 경우만 센다
```

`tight` 는 **강요된 한 수**만 센다. 다른 선택지가 하나도 남김없이 다 져야 1이다.
그래서 드물 수밖에 없고 — `lost` 가 95% 인데 `tight` 가 4% 인 모순이 이걸로 설명된다.
**둘이 다른 걸 재고 있었다.**

판이 조이는 정도는 *"다른 수 가운데 몇 %가 지는가"* 가 훨씬 잘 잡는다.
`hard.js` 에 **압박(press)** 을 넣었다 — 정답 위 각 자리에서 `지는 수 / 전체 대안` 의 평균.

> 🔴 **고르기 전에 자를 확인한 것이 값을 했다.** 그대로 `tight` 로 골랐으면
> 위키 함정(*"고를 게 없어서 유일했다"*)을 그대로 다시 밟았을 것이다.

그리고 생성기는 이미 `a.shortest !== 1` 로 **최단해가 유일한 판만** 받고 있었다.
유일한데도 안 어려운 이유가 여기 있다 — 최단이 하나라는 것과
**틀린 수가 벌을 받는다는 것**은 다른 이야기다.
